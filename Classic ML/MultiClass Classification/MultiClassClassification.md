## One-vs-Rest (OvR) Classification

### 1. Общая идея подхода

**One-vs-Rest (OvR)** — это стратегия многоклассовой классификации,  
в которой каждый класс поочерёдно противопоставляется **всем остальным классам**.

Если в задаче присутствует `K` классов, то обучается:
- **K бинарных классификаторов**

Каждый классификатор отвечает на вопрос:

> «Принадлежит ли объект данному классу или нет?»

---

### 2. Формирование обучающих данных

Для каждого класса `c`:

- Все объекты класса `c` помечаются как **1**
- Все объекты остальных классов помечаются как **0**

Таким образом:
- исходная многоклассовая задача
- преобразуется в `K` бинарных задач

Каждый классификатор обучается **на всей выборке**, но с разной бинарной разметкой.

---

### 3. Предсказание класса

Для нового объекта:

1. Он подаётся **на все K бинарных классификаторов**
2. Каждый классификатор выдаёт:
   - вероятность принадлежности своему классу
3. Выбирается класс с **максимальной вероятностью**

📌 Итоговое правило:
> объект относится к тому классу, который «увереннее всех» в своём решении.

---

### 4. Интуитивная интерпретация

Можно представить, что каждый класс:
- «защищает сам себя»
- соревнуется со всеми остальными одновременно

Класс с самым сильным «аргументом» (вероятностью) выигрывает.

---

### 5. Преимущества и недостатки

**Плюсы**
- Простая реализация
- Линейная сложность по числу классов
- Хорошо масштабируется

**Минусы**
- Классификаторы обучаются независимо
- Вероятности могут быть некорректно откалиброваны
- Не учитываются отношения между классами

---

### 6. Краткая формулировка для отчёта

> В стратегии One-vs-Rest многоклассовая задача сводится к обучению одного бинарного классификатора на каждый класс, где итоговое решение принимается по максимальной вероятности.

## One-vs-One (OvO) Classification

### 1. Общая идея подхода

**One-vs-One (OvO)** — стратегия многоклассовой классификации,  
в которой каждый класс сравнивается **с каждым другим классом**.

Если в задаче присутствует `K` классов, то обучается:
- **K·(K−1)/2 бинарных классификаторов**

Каждый классификатор различает **только одну пару классов**.

---

### 2. Формирование обучающих данных

Для каждой пары классов `(c₁, c₂)`:

- Из обучающей выборки выбираются **только объекты этих двух классов**
- Остальные классы полностью игнорируются
- Метки перекодируются:
  - `c₁ → 1`
  - `c₂ → 0`

Таким образом:
- каждая модель решает **простую бинарную задачу**
- на уменьшенной и более однородной выборке

---

### 3. Предсказание класса (голосование)

Для нового объекта:

1. Он подаётся **на все парные классификаторы**
2. Каждый классификатор:
   - выбирает один из двух классов
   - отдаёт ему **один голос**
3. Итоговый класс определяется по принципу:
   - **большинства голосов**

📌 Это называется **мажоритарное голосование**.

---

### 4. Интуитивная интерпретация

Можно представить турнир:

- каждый класс соревнуется с каждым
- за победу в паре начисляется голос
- побеждает класс, выигравший больше всего «матчей»

---

### 5. Преимущества и недостатки

**Плюсы**
- Каждая модель решает простую задачу
- Хорошо аппроксимирует сложные границы
- Часто даёт более высокое качество

**Минусы**
- Квадратичный рост числа моделей
- Высокие вычислительные затраты
- Плохо масштабируется при большом числе классов

---

### 6. Краткая формулировка для отчёта

> В стратегии One-vs-One многоклассовая классификация осуществляется путём голосования между всеми парными бинарными классификаторами, обученными для каждой пары классов.

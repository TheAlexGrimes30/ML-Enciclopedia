## RAG (Retrieval-Augmented Generation)

RAG — это **модель генерации текста с использованием извлечённых документов**, которая объединяет **retriever** и **генеративный трансформер**.  
Модель была предложена Facebook AI и хорошо подходит для генерации текста, ответов на вопросы, суммаризации и других задач, где требуется **внешний контекст**.

---

### 🔹 Основная идея RAG

RAG сочетает **retrieval (извлечение документов)** и **generation (генерацию текста)**:

1. **Retriever (извлечение документов)**  
   - Получает **входной запрос**.  
   - Использует **эмбеддинги запросов и документов** (например, BERT или другой sentence encoder).  
   - Находит наиболее релевантные документы с помощью **косинусного сходства** или других метрик.  
   - Формирует контекст для генерации текста.

2. **Generator (генеративная модель, GPT/T5)**  
   - Получает **входной запрос + retrieved документы**.  
   - Генерирует ответ **авторегрессионно** (токен за токеном).  
   - Может использовать **top-k, top-p sampling** для контроля разнообразия текста.

3. **Text-to-Text формат (опционально)**  
   - Входной текст: запрос + retrieved документы  
   - Выходной текст: сгенерированный ответ  

---

### 🔹 Применение

- **Question Answering (QA)**  
- **Диалоговые системы и чат-боты**  
- **Суммаризация с внешним контекстом**  
- **Генерация инструкций или документации на основе базы знаний**  
- **Пояснение или расширение текстов с использованием внешних источников**

---

### 🔹 Механизмы работы

1. **Query Embedding**  
   - Запрос кодируется с помощью BERT-подобного энкодера.  
   - Получаем CLS токен или pooled embedding запроса.

2. **Document Embedding & Retrieval**  
   - Предвычисленные эмбеддинги документов нормализуются.  
   - Находим top-k документов по косинусной близости к запросу.

3. **Context Concatenation**  
   - Запрос и retrieved документы объединяются в одну последовательность.  
   - Для генератора это становится **входом модели**.

4. **Autoregressive Generation (GPT/T5)**  
   - Генеративная модель получает вход (query + documents).  
   - Генерирует текст токен за токеном.  
   - Используется **causal masking**, top-k и top-p sampling.

5. **Output Projection (LM Head)**  
   - Линейный слой преобразует скрытые состояния декодера в логиты по словарю.  

---

### 🔹 Архитектурные особенности

- **Retriever:** BERT или Sentence Transformer  
- **Generator:** GPT, T5 или другой autoregressive Transformer  
- **Embedding-based Retrieval:** cosine similarity для выбора релевантных документов  
- **Fusion:** query + retrieved documents как input генератора  
- **Top-k / Top-p Sampling:** для контролируемой генерации  

---

### ✅ Преимущества RAG

- Позволяет использовать **внешние знания** для генерации текста  
- Генератор обучается **с учетом retrieved контекста**, повышая точность  
- Универсален для **QA, диалогов, суммаризации и генерации текста**  
- Можно использовать с **разными генеративными моделями** (GPT, T5, BART)  
- Масштабируемость: можно увеличивать размер базы знаний без дообучения генератора

---

### ⚠️ Недостатки

- Требуется **хранилище и индексация внешних документов**  
- Медленнее обычной генерации из-за retrieval step  
- Для больших баз знаний нужны **вычислительные ресурсы и память**  
- Качество зависит от **retriever**: плохой retrieval → плохой ответ
